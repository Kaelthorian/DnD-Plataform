# Player i18n

English is the default and source language for player-facing UI text.

Spanish is the only supported player translation. Every English key in `src/app/renderer/i18n.js` must have a matching Spanish key in the source Spanish dictionary.

## Adding Text

1. Add the English string to the `EN` dictionary in `src/app/renderer/i18n.js`.
2. Add the same key to the `ES` dictionary with the Spanish translation.
3. Use the key from HTML or JavaScript instead of hardcoding visible text.

For static HTML, use the existing data attributes:

```html
<button data-i18n="common.add">Add</button>
<input data-i18n-placeholder="common.search" placeholder="Search...">
<button data-i18n-aria-label="common.close" aria-label="Close">X</button>
```

For JavaScript, use `t(key, params)` for known keys:

```js
showStatus(t("export.copied", { count: code.length }));
```

Use `translateDynamicText(key, fallback, params)` only when dealing with legacy or generated strings that are not yet fully keyed.

## Validation

Run:

```powershell
npm run test:i18n
```

`npm test` also runs the i18n validation.

The validation fails when an English key is missing from Spanish, or when placeholders such as `{count}` differ between English and Spanish. It also warns about obvious hardcoded player-facing strings in renderer files. To temporarily treat hardcoded string warnings as failures, run:

```powershell
$env:I18N_STRICT_HARDCODE="1"; npm run test:i18n
```

## Do Not Translate

Do not translate stable internal identifiers or external data keys:

- Save keys and localStorage keys.
- PDF field names.
- Protocol payload types and WebSocket message names.
- Engine constants and action IDs.
- Ability keys such as `str`, `dex`, `con`, `int`, `wis`, `cha`.
- Item, spell, class, feat, race, background, and source identifiers used for lookup.
- File paths, selectors, data attributes, IPC channel names, and Electron handler names.

## Rule

No new visible player-facing string should be hardcoded directly in HTML, JSX, or JS. Add a dictionary key first, keep English as source, and add the matching Spanish translation in the same change.
